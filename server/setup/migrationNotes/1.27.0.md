# 1.27.0 migration notes

## Stacked access-rules-only policies (resource rule policies)

Schema: added `resourceRulePolicies` table (both pg and sqlite) with columns `id`
(serial/integer PK), `resourceId` (FK → `resources`, cascade), `resourcePolicyId`
(FK → `resourcePolicies`, cascade), `position` (varchar/text, `"before" | "after"`,
default `"after"`), `sortOrder` (integer, default 0), `enabled` (boolean, default
true); index on `resourceId`, unique index on (`resourceId`, `resourcePolicyId`).
Widened `resourcePolicies.scope` allowed values to include `"rules-only"` (varchar/text
column, no schema change needed).

Steps the migration script must do in code:
1. Nothing required — the new table starts empty and the widened `scope` value is only
   written by the new create handler.

Notes: drizzle generates the `CREATE TABLE` + indexes for both drivers. No backfill,
no data copies, no config changes. On OSS builds the table exists but stays empty
(the routes that write it are enterprise-only).
